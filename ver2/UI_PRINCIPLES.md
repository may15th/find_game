# FIND!! V2 UI 원칙과 변경 기록

UI 방식을 변경할 때 이 문서의 현재 원칙과 변경 이력을 함께 갱신한다. 구현 내용, 의도, 검증 결과 및 미검증 범위를 기록한다.

전문가·게임 사례와 출처, 아트·효과 명세는 [DESIGN_RESEARCH.md](DESIGN_RESEARCH.md)에 정리한다. 아래 기존 원칙과 함께 적용한다.

## 적용 범위

박지민 태블릿 납품 사건 하나만 구현한다. 배포 실행 진입점은 루트 `index.html`이며 구현은 `ver2/`에서 관리한다. 기존 게임은 `index_ref.html`로 이름만 변경해 보존한다. 참고용 원본의 내용은 수정하지 않는다.

## 스토리 화면 원칙

- 네이비·크림·골드를 기본 색상으로 사용한다.
- 대화창에는 현재 화자의 대사 하나만 표시하고 화자 이름을 별도로 표시한다.
- 캐릭터 좌측 상단의 면담실·직함 표시는 사용하지 않는다.
- 캐릭터 좌측 하단 명패는 항상 `박지민 / 미래정보 대표`로 표시한다. 현재 화자 이름과 인적정보를 구분한다.
- 박지민 발화 시 캐릭터와 명패는 기본 크기로 표시하고 원래 색상·명도를 유지한다.
- 감사관·내레이션·후속조치 발화 시 캐릭터는 좌측 하단에서 58% 크기로 표시하며 채도와 명도를 낮춘다. 명패도 동일한 58% 비율로 축소한다. 명패 자체에는 흑백 필터를 적용하지 않는다.
- 화자 전환 시 캐릭터와 명패 크기를 0.25초 동안 함께 전환한다. 대화창 위치는 고정한다. 동작 줄이기 설정에서는 애니메이션을 생략한다.

## 시작 연출

- 최초 실행 및 사건 다시 플레이 시 검은 화면에서 사건 개요를 먼저 제시한다.
- 신고 경위, 계약가와 온라인 가격, 박지민의 입장, 플레이어의 감사관 역할을 설명한다. 정답과 사양 차이는 미리 공개하지 않는다.
- 본문은 35ms 간격으로 한 글자씩 표시한다. 내용 영역의 높이를 예약해 버튼이 타이핑에 따라 밀리지 않게 한다.
- `전체 내용 보기`로 타이핑을 즉시 완료할 수 있다. 완료 후 `조사 시작` 버튼으로 면담에 진입한다. 자동으로 넘기지 않는다.
- 시작 연출 중에는 탭과 좌우 스와이프로 조사를 건너뛸 수 없다.
- 동작 줄이기 설정에서는 전체 내용을 즉시 표시한다. 스크린 리더에는 완성된 본문을 제공한다.

## 변경 이력

### 2026-11-13 · 배포 진입점 변경

사용자 요청으로 V2의 `index_ver2.html`을 `index.html`로 변경했다. 기존 `index.html`은 `index_ref.html`로 보존하고 해시가 동일함을 확인했다. 브랜드 링크와 자동 테스트의 진입점 경로를 갱신했다. 아래 이전 이력에 나오는 파일명은 당시 기준이다.

### 2026-11-13 · 리서치 기반 아트·UX 강화

- Lucas Pope의 Obra Dinn 기고, Hannah Kennedy의 Pentiment 제작기, Overboard 개발진 인터뷰, NN/G 게임 UX, Game Accessibility Guidelines 및 W3C를 직접 조사했다. 출처 요약과 프로젝트 적용 해석을 구분해 별도 문서화했다.
- 시각 방향은 잉크 네이비·황동·종이 기록물. 제공 캐릭터는 유지하고 조사실 배경은 자체 제작 SVG로 보강했다. 기존 배경 PNG는 보존한다.
- 문서 카드에 서류철 모티프, 진술·매뉴얼·노트에 종이 재질과 일관된 정보 계층을 적용했다.
- 상단 작업 안내와 기록 수, 기록/해제 알림, 요건 작성 수를 표시한다. 작성 여부는 정답 여부를 뜻하지 않는다.
- 판정서 검토 창에서 선택한 답변·개별 근거·판정을 확인하고 수정하거나 최종 제출할 수 있다. 결과 화면의 두 행동 제한은 유지한다.
- 화면 설정에 큰 글씨·효과 줄이기를 추가했다. OS 동작 줄이기 설정을 존중한다. 소리·섬광·반복 배경 운동은 추가하지 않았다.
- 정보 기록 후 키보드 포커스는 같은 정보 버튼에 유지한다. 강조 구절은 버튼 내부의 한 텍스트 블록으로 묶어 모바일에서 단어 단위로 흐르게 한다.
- 구현 파일: `css/design-system.css`, `js/presentation.js`, `assets/case02/background/interview-room-v2.svg` 및 관련 UI·게임 코드.
- 검증: 자동 플레이 흐름·제출 검토/취소·개별 근거 기록/해제·설정·대비·에셋 경로·원본 해시. 실제 브라우저와 모바일 시각 검증은 도구 연결 제한으로 미완료.

### 2026-11-13 · 서류 기록 → 문서 선택 → 개별 근거 채택

- 상위 3개 화면은 유지하고 증거·매뉴얼 화면 안에 `계약·증빙 서류` / `업무 매뉴얼` 하위 탭을 둔다.
- 서류를 열면 본문과 함께 클릭 가능한 주요 정보가 표시된다. 개별 정보를 선택/해제해 조사 노트에 기록한다. 열람만 한 문서는 근거 목록에 자동 추가하지 않는다.
- 업무 매뉴얼은 별도 읽기 화면이며 증거 수집 대상으로 취급하지 않는다. 조사 노트는 양쪽 하위 탭에서 확인할 수 있다.
- 요건 검증에는 조사 노트에 기록된 정보가 있는 문서만 표시한다. 문서를 펼치면 그 문서에서 기록한 하부 정보만 나타난다.
- 하부 정보를 선택하면 해당 요건의 근거로 채택한다. 동일 정보를 여러 요건에 사용할 수 있으며 복수 선택과 해제가 가능하다.
- 서류에서 정보 기록을 해제하면 모든 요건에 채택된 해당 근거도 해제한다. 화면 이동 시 예/아니요와 근거 선택을 유지한다. 재플레이 시 모두 초기화한다.
- 판정 검증과 결과 보고서는 문서 이름뿐 아니라 선택한 개별 정보까지 사용한다. 가격 요건은 계약·판매 가격, 동등성은 RAM·보증 비교, 납품 일치는 계약·검수 모델 및 사양을 대조한다.
- 자동 검증 범위: 개별 정보 기록·해제, 수집한 문서·정보 필터링, 세 판정 분기, 결과 보고 및 재플레이. 실제 모바일 시각 검증은 별도 필요.

### 2026-11-13 · 정보 강조와 화자 구별

4종 정보 강조색·범례, 인적정보 명패, 캐릭터 축소·흑백 및 발화 시 복원 적용. 3가지 판정 흐름 자동 테스트 통과. 실제 브라우저 레이아웃 검증은 도구 연결 오류로 미완료.

### 2026-11-13 · 명패 비율과 사건 도입

명패도 캐릭터와 동일 비율로 축소하도록 수정. 검은 시작 화면과 타이핑 개요, 전체 내용 보기 및 조사 시작 추가. 재플레이 시 도입도 다시 시작. 자동 흐름 검증에 도입 완료·진입과 재플레이를 포함한다. 실제 모바일 시각 검증은 별도로 필요하다.
