# FIND!! V2 — 디자인 리서치와 적용 명세

조사일: 2026-11-13. 대상: 박지민 태블릿 납품 사건 단일 프로토타입.

배포 진입점 변경: V2는 현재 루트 `index.html`에서 실행하며, 기존 게임은 `index_ref.html`로 내용 변경 없이 보존한다. 아래 원본 해시 보존 설명은 이 참고 파일을 뜻한다.

## 디자인 방향

**조용한 조사실, 손으로 정리하는 사건 기록.** 인물은 따뜻한 색과 큰 실루엣으로, 조사 도구는 차가운 네이비로, 읽고 판단하는 기록은 크림색 종이로 구분한다. 플레이어가 느낄 긴장은 서류의 차이와 판정의 책임에서 나온다. 효과는 행동을 확인하고 장면의 무게를 전달하는 데 사용한다.

아래의 ‘출처 내용’은 원문을 요약한 것이며, ‘FIND 적용’은 본 프로젝트를 위한 해석과 구현 결정이다. 원작 화면·폰트·캐릭터·음원을 복제하지 않는다. ‘명작’은 객관적 순위로 단정하지 않고 제작 과정이 공개되어 분석 가능한 추리·서사 게임을 선정했다.

## 2. UI·UX 규칙

- **조사의 주도권:** 답을 정답색으로 표시하지 않는다. 진행 수치는 작성·기록 상태만 뜻한다. 점수와 다른 사건 메뉴는 없다.
- **고정된 정보 계층:** 사건 제목 → 현재 작업 안내 → 콘텐츠 → 다음 행동. 탭은 아이콘·번호·문구로 구분하고 현재 위치를 명확하게 표시한다.
- **기억 부담 감소:** 조사 노트에 원문 정보와 출처를 함께 표시한다. 요건의 채택 근거도 출처와 정보를 함께 읽을 수 있게 유지한다.
- **기록과 채택의 구별:** 자료실의 ‘기록됨’은 조사 노트에 보관했다는 뜻이다. 요건 검증의 ‘채택’은 특정 질문에 연결했다는 뜻이다. 두 상태에 같은 단어를 쓰지 않는다.
- **중요 행동의 오류 예방:** 판정서 제출 시 요건 답변과 근거를 요약한 검토 창을 연다. ‘계속 검토’ 또는 ‘최종 제출’을 선택한다. 정답은 보여주지 않는다.
- **모바일 리듬:** 휴대폰은 한 열, 넓은 화면은 장면과 진술 또는 서류 카드를 두 열로 배치한다. 긴 문서는 대화창과 별개로 스크롤하고 닫기 버튼은 접근 가능한 위치에 둔다.
- **가독성:** UI는 시스템 산세리프, 사건 제목은 시스템 명조 계열을 사용한다. 외부 웹폰트는 로드하지 않는다. 숫자는 고정폭 숫자를 적용한다. 본문은 한국어 단어 단위로 줄바꿈한다.

## 3. 아트 규칙

- 색상: 잉크 네이비 `#0b1a24`, 패널 `#142e3c`, 종이 `#f7efdd`, 황동 골드 `#eac782`, 보조 글자 `#b5c5cd`.
- 강조색: 기존 파랑/노랑/초록/보라 의미를 보존한다. 상호작용 선택 표시는 별도 체크 아이콘과 텍스트로 병기한다.
- 배경: 기존 PNG는 보존하고, 방의 깊이·서류장·창문·펜던트 조명·책상을 코드 기반 SVG로 보강한다. 장식적 도형은 저대비로 유지한다.
- 인물: 제공된 8종 PNG를 유지한다. 발화 시 원색·큰 크기, 비발화 시 좌측 하단 58%·옅은 흑백. 명패도 같은 비율로 변한다.
- 재질: 배경은 매트한 잉크, 문서는 밝은 종이, 선택 도구는 얇은 금속성 테두리. 모든 카드를 같은 색·같은 깊이로 만들지 않는다.
- 실제 기관의 로고·공식 인장처럼 오해할 수 있는 장식은 사용하지 않는다. 문서 번호와 ‘기록 완료’ 스탬프는 게임 내부 표현이다.

## 4. 효과 규칙

| 이벤트 | 시각 효과 | 목적 |
| --- | --- | --- |
| 장면 진입 | 짧은 페이드·최대 6px 이동 | 맥락 전환 |
| 화자 전환 | 기존 250ms 인물·명패 확대/축소 | 현재 발화자 식별 |
| 자료 열기 | 짧은 종이 패널 등장 | 서류를 여는 감각 |
| 정보 기록·해제 | 체크 상태와 상태 알림 | 입력 결과 확인 |
| 근거 채택 | 선택 테두리·채택 수 갱신 | 질문과 증거 연결 확인 |
| 판정 검토 | 전체 요약과 제출/수정 동작 | 오조작 예방 |
| 사건 완료 | 짧은 기록 완료 스탬프 등장 | 사건 마무리 |

상시 화면 흔들림·섬광·자동 카메라 이동·정답을 암시하는 감정별 색조는 사용하지 않는다. 효과를 꺼도 모든 상태를 텍스트·도형으로 확인할 수 있어야 한다. 배경음과 효과음은 이번 적용에 추가하지 않는다. 사운드는 별도의 음향 방향과 볼륨·뮤트 UX를 정한 후 도입한다.

## 5. 이번 적용 및 검증

- 구현: 공통 디자인 토큰, 문서철 형태의 카드, 종이 진술 패널, SVG 조사실, 작업 안내, 기록 피드백, 요건 작성 수, 판정 검토 창, 큰 글씨·효과 설정, 짧은 상태 기반 효과.
- 유지: 단일 사건, 문서→정보 기록→요건별 채택 흐름, 8종 감정, 세 판정 분기, 원본 보존 파일 `index_ref.html`, 로컬 파일 실행.
- 자동 검사: 세 판정의 도입부터 결과·재플레이까지, 근거 필터·해제, 제출 검토/취소, UI 설정, 강조색 대비, 상대 에셋 경로, JS 문법, 원본 해시.
- 제한: 현재 브라우저 접근 호스트가 없고 대상 Chrome 창은 최소화 상태라 실제 모바일 렌더링·키보드·터치 시각 검증을 완료하지 못했다. 자동 검증을 사용자 플레이테스트와 동일시하지 않는다.

## 6. 다음 플레이테스트에서 확인할 가설

아래는 연구 결과로 확정된 효과가 아니라 이번 디자인의 검증 대상이다.

1. 별도 설명 없이 첫 자료를 열고 정보를 기록할 수 있는가?
2. 기록과 요건별 채택의 차이를 이해하는가?
3. 모바일에서 대사·선택 문구·닫기/다음 버튼이 잘리거나 가려지지 않는가?
4. 색상과 효과를 제거해도 동일한 조사를 진행할 수 있는가?
5. 효과가 자료 읽기를 방해하지 않고 행동의 결과를 분명하게 하는가?
